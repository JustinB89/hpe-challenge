Crash / DoS break against kevwjin (team 106) — a long -k value makes register
run far longer than 60 seconds (timeout counts as a crash).

Root cause (build/stor.c):

  pbkdf2_sha256() (lines ~227-251) runs PBKDF2_ITERS (20000) HMAC iterations per
  derived block, and KEY_MATERIAL_LEN (64) needs 2 blocks => ~40000 HMAC calls.
  Each call is hmac_sha256(password, pass_len, ...) (line ~241), and
  hmac_sha256 (lines ~174-187) re-hashes the ENTIRE password every time when
  key_len > 64:

      if (key_len > 64) { sha256_init/update(password, key_len) ... }   // O(key_len)

  So the total work is ~40000 * key_len bytes of SHA-256. The password length is
  unbounded (it comes straight from argv -k). For a ~120000-byte key that is
  ~4.8 GB of SHA-256 at -O0/32-bit, which takes well over 60 seconds.

Exploit: a single command on a fresh database (no enc.db):
    stor -u a -k <120000 'A' characters> register

The key is 120000 bytes, comfortably under the Linux 128 KiB single-argument
limit (MAX_ARG_STRLEN) so execve accepts it, and the test.json is far under the
600 MB input cap.

Verification (freshly built binary): with key length 120000 the register command
did not finish within a 75-second timeout (rc=124), whereas keys of length 20000
and 60000 finished quickly. >60 s => crash category.
