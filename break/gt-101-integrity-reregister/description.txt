Integrity break against GT (team 101) — re-registering a user overwrites their
credentials AND explicitly wipes all their file contents, with no key required.

Root cause (build/stor.c, do_register, lines ~371-386):

    UserEntry *u = find_user(db, username);
    if (u) {                                   // username already exists
        memcpy(u->salt,     salt,     SALT_LEN);   // overwrite with attacker key
        memcpy(u->auth_tag, auth_tag, HMAC_LEN);
        for (j = 0; j < u->num_files; j++) {       // <-- destroy every file
            FileEntry *fe = &u->files[j];
            secure_wipe(fe->ciphertext, fe->content_len);
            free(fe->ciphertext); fe->ciphertext = NULL;
            fe->content_len = 0;
            secure_wipe(fe->iv, IV_LEN);
            secure_wipe(fe->content_hmac, HMAC_LEN);
        }
    }

register never rejects an existing username and requires no proof of the old
key. Re-registering user1 replaces its salt/auth_tag and frees/zeroes every
file's ciphertext.

Exploit (single keyless command, runs on the provided enc.db):
    stor -u user1 -k attacker register

Verification (freshly built binary, provided enc.db): register returns rc=0 and
rewrites enc.db. Reading user1/file1 afterwards with the original key returns
"invalid" (rc 255) instead of the original INTEGRITY_FLAG. The grader re-reads
user1/file1 with the real key and sees different content -> integrity break.
